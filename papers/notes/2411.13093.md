# Video-RAG: Visually-aligned Retrieval-Augmented Long Video Comprehension
arXiv 2411.13093v4 (NeurIPS 2025) · Xiamen Univ / Nanjing / Rochester
Code: https://github.com/Leon1207/Video-RAG-master

## Core contribution
Training-free, plug-and-play RAG layer for **any** LVLM. Instead of feeding more frames,
feed *fewer frames + query-relevant auxiliary TEXT* extracted from the video by cheap
open-source tools (OCR, ASR, open-vocab detection). The auxiliary text is "visually
aligned" — it describes what is actually in the pixels — so it closes the modality gap
rather than adding generic captions.

Headline: +2.8% avg on Video-MME across 7 LVLMs for only ~2.0K extra text tokens
(≈14 frames' worth). 72B LLaVA-Video + Video-RAG = 77.4% vs GPT-4o 77.2%.

## Exact method (3 phases)

**Phase 1 — Query Decouple.** The LVLM sees ONLY the text query (no frames) and emits a
JSON retrieval request:
```json
{"ASR": "<paraphrase of what might be said>",
 "DET": ["book","table"],          // physical entities to detect
 "TYPE": ["num","loc","rel"]}      // which object facts are needed
```
Any field may be NULL. They post-filter `DET` with **spaCy** to keep only concrete
CLIP-sensitive nouns (drops abstract concepts like "safety", "incident"). ← cheap, do this.

**Phase 2 — Auxiliary text generation (3 DBs, built in parallel).**
- `DB_ocr`: EasyOCR on every sampled frame → per-frame text → Contriever embeddings → FAISS.
- `DB_asr`: Whisper on extracted audio → chunked → Contriever → FAISS.
- `DB_det`: **keyframes only.** Compute CLIP similarity between `R_det` and sampled frames,
  keep frames with sim > t; run APE (open-vocab detector) on just those with `R_det` as the
  text prompt. This is the compute-saving trick — detection is the expensive tool, so it is
  gated by a cheap embedding filter.

**Phase 3 — Retrieval + integration.**
- Encode `Concat(R, Q)` with Contriever → FAISS `IndexFlatIP` → keep chunks with sim > t.
- Raw detector output (`category: [x,y,w,h]`) is unreadable to an LVLM, so it is converted
  to a **scene graph** and verbalized into three text types selected by `R_type`:
  - Location: "Object {id} is a {cat} located at [x,y] with dimensions {w×h}"
  - Counting: "Object counting: - {cat}: {n}"
  - Relation: "Object {id} ({cat}) is <left of / above / near> Object {id} ({cat})"
- Merge OCR+ASR+DET **chronologically**, concat with query, feed with the sampled frames.

## Headline numbers (with conditions)
| Setting | Result |
|---|---|
| Video-MME, 7 LVLMs, official frame budgets, A100 80G | +2.8% avg over *with-subtitles* baseline |
| LongVA-7B @128f | 56.0 → 62.0 (+6.0) — biggest gain of the seven |
| LLaVA-Video-72B @64f | 75.9 → 77.4, beats GPT-4o (77.2) |
| MLVU 7B / 72B | 70.8→72.4 / 73.1→73.8 |
| LongVideoBench 7B / 72B | 56.6→58.7 / 61.9→65.4 |
| Extra cost on a 7B | +8 GB GPU mem, +5 s per query |

**Ablation (Long-LLaVA-7B, 32f, Video-MME) — the ordering matters:**
none 52.0 → +DET 52.9 → +OCR 55.7 → +ASR 59.8(all, no RAG) → **+RAG filtering 62.1**.
So: (a) ASR is the single biggest contributor, (b) RAG filtering itself is worth **+2.3%**
over dumping all auxiliary text in (59.8 → 62.1), (c) DET alone is the weakest (+0.9).

**Threshold sweep (the most useful table in the paper), t on both CLIP and FAISS sim:**
| t | aux tokens | time/query | overall |
|---|---|---|---|
| 0.0 (everything) | 3.6K | 36 s | 62.0 |
| 0.2 | 2.7K | 18 s | 61.8 |
| **0.3** | **1.9K** | **11 s** | **62.1** ← chosen |
| 0.4 | 0.8K | 8 s | 60.6 |
| 0.5 | 0.3K | 7 s | 56.1 |
| 1.0 (nothing) | 0 | 6 s | 52.0 |
| random 1.9K tokens | 1.9K | 11 s | 59.1 ← retrieval really is doing work |
**t = 0.3 is 3× faster than t = 0 at equal accuracy.** Free win, take it.

**Indexing cost is the real bottleneck (Table 8, Video-MME-mini):**
ASR 21 min, OCR 2 min, DET 3 min at 16 frames — but at 384 frames: ASR 42, OCR 48, DET 24 min.
Inference is only 5–11 s. Databases build in parallel so total = max(), not sum().

## Stated limitations
- Bounded by the quality of the fixed external tools; no adaptation to domain.
- Frame sampling is uniform and static — they name adaptive frame selection as future work.
- Single-turn retrieval only: no ability to go back and look again if the first retrieval missed.

## What we steal for a 7-hour hackathon on CCTV/drone footage
1. **The whole skeleton.** This is our §3 architecture, validated. Training-free, all
   open-source, no hosted API → matches our data-sovereignty constraint exactly.
2. **Query Decouple as a JSON step.** Qwen3-VL-4B in text-only mode emits
   `{"DET": [...], "OCR": ..., "TYPE": [...]}`. Cheap, and it gives our open-vocab detector
   (SAM 3 / YOLO-World) its text prompt for free. Add spaCy noun filtering.
3. **Gate the expensive tool with a cheap embedding filter.** Their CLIP-sim → APE gate is
   the same shape as our motion prefilter → enrich gate. Generalize it: *motion energy* AND
   *SigLIP2 sim* both gate whether a chunk gets captioned/detected. Two-stage gating is the
   measurable compute story for our demo.
4. **Verbalize detections into a scene graph.** Raw boxes are useless to a VLM. For
   surveillance this is where "person near gate", "vehicle beside barrier" comes from —
   the relation strings are literally spatial-security predicates. High value, ~40 lines.
5. **t = 0.3 as our starting threshold**, and *replicate their sweep* on our own footage.
   A threshold-vs-latency-vs-recall table is exactly the "measurable performance" artifact
   the judges asked for, and it costs one loop over an already-built index.
6. **The random-baseline row.** Retrieving 1.9K *random* tokens scores 59.1 vs 62.1 retrieved.
   Steal this ablation design: it proves our retrieval works, not just our VLM. Cheap and
   very convincing on a slide.
7. **Report ASR/OCR/DET build time separately and note they parallelize.** Our index-time
   table should have the same shape.

## Caveats for our setting
- **ASR is their biggest win and we probably have no audio.** CCTV is usually silent. Expect
  the gain profile to shift entirely onto DET + OCR, and DET was their *weakest* component
  (+0.9). This is precisely the gap our motion/event-aware scorer should fill — worth stating
  explicitly as our motivation.
- OCR on CCTV pays off differently than on their web video: burnt-in timestamps, camera IDs,
  licence plates, signage. Burnt-in timestamp OCR is a near-free way to get *absolute* time
  into every chunk record — very useful for a security product, and a nice demo detail.
- EasyOCR → swap for RapidOCR/PaddleOCR (faster, better on small text). Contriever → BGE-small
  or just BM25 + SigLIP2; Contriever is dated and adds a model download.
